CGI(Common Gateway Interface)
- 요청이 올때마다 새로운 프로세스를 생성하는 방식 (외부프로그램을 통해)

1997년 Servelet 등장 - 자바로 HTTP 요청을 처리
프로그램 하나만 켜두고 요청이 오면 쓰레드만 새로 생성해서 처리
ex> System.out.println("<h1> 안녕하세요 </h1>"); - 아직 복잡하다.

(2000 ~) JSP(Java Server Pages) 등장.
HTML 기반 파일에 <% 자바코드 %>
HTML은 디자이너가 하고, 자바 로직은 개발자가 작성
동적 데이터 바인딩 가능
여전히 프론트엔드와 백엔드의 소통이 어렵고 코드가 어려움
<html> <body>
	<h1> 안녕하세요, <%= request.getParameter("name") %> 님! </h1>
</body> </html>

<MVC 구조>
Controller - 중간 다리 역할
View - 화면
Model - 데이터 및 로직

유지보수성이 향상

ex) 회원가입 흐름
1. 화면(UI) 로직 : HTML 폼에서 이름, 이메일, 비밀번호 입력 후 "가입" 버튼 클릭 (주소)
2. (주소로 받아서) Controller: 요청을 받아서 (메서드 실행) Service 계층 호출
3. Service 계층(비지니스 로직) :
	- 비밀번호 암호화
	- 이메일 중복 여부 확인
	- 이메일 형식 검증
	- 가입 완료 시 환영 메일 발송
4. DAO/Repo 계층 (데이터 접근)
	- DB에 연결하여 INSERT 쿼리 실행

Spring - 자바 웹 개발을 쉽게 하게끔 도와주는 프레임워크
 - 의존성 주입(DI): 객체를 알아서 만들어주고 적절한 타이밍에 주입해준다 
 - 제어의 역전(IoC): "내가 알아서 다 관리하겠다."
 - 관점 지향 프로그래밍: "여러 파트로 나누겠다."

SpringBoot - 스프링 사용을 쉽게 해 주는(한 방에) 프로젝트
ㄴ> 다양한 어노테이션 효과
@SpringBootApplication — 부트 애플리케이션 시작점, 자동설정 + 컴포넌트 스캔 — Spring Boot
@Controller — 요청 처리 후 뷰 반환 — Spring MVC
@RestController — JSON 응답 전용 컨트롤러 — Spring MVC
@GetMapping — GET 요청 매핑 — Spring MVC
@PostMapping — POST 요청 매핑 — Spring MVC
@PathVariable — URL 경로 변수 매핑 — Spring MVC
@RequestParam — 쿼리 파라미터/폼 데이터 매핑 — Spring MVC
@RequestBody — 요청 바디(JSON)를 객체로 변환 — Spring MVC + Jackson
@ResponseBody — 반환 값을 HTTP 바디에 직렬화 — Spring MVC + Jackson
@Service — 서비스 계층 컴포넌트 지정 — Spring Framework
@Repository — DAO/데이터 접근 계층 지정, 예외 변환 — Spring Framework
@Component — 일반 컴포넌트 등록 — Spring Framework
@Autowired — 의존성 주입 — Spring Framework
@RequiredArgsConstructor — final 필드 기반 생성자 자동 생성 — Lombok
@NoArgsConstructor — 파라미터 없는 기본 생성자 자동 생성 — Lombok
@AllArgsConstructor — 모든 필드를 받는 생성자 자동 생성 — Lombok
@Entity — JPA 엔티티 클래스 매핑 — JPA/Hibernate
@Id — 엔티티 기본키 필드 지정 — JPA/Hibernate
@GeneratedValue — PK 생성 전략 지정 — JPA/Hibernate
@Column — 컬럼 매핑/제약 지정 — JPA/Hibernate
@Table — 테이블 이름 매핑 — JPA/Hibernate
@Transactional — 트랜잭션 경계 지정 — Spring Tx
@Valid — 요청 DTO 검증 활성화 — Jakarta Bean Validation
@NotNull — null 불가 제약 — Jakarta Validation
@Size — 문자열/컬렉션 크기 제약 — Jakarta Validation
@Builder — 객체 생성 빌더 패턴 적용 — Lombok
@Getter — 게터 자동 생성 — Lombok

DB 쪽 :
JDBC(Java DataBase Connectivity) -

JPA - SQL 작성 없이 객체(Entity) 중심 개발

JDBC - 콘솔 기반(뷰 X) 회원 관리 프로그램 (CRUD 기능) - mySQL 연결 - maven

JDBC(Java Database Connectivity) - 자바에서 데이터베이스에 접속할 수 있도록 하는 자바 API

CRUD(CREATE READ UPDATE DELETE) - 데이터 조작의 기본 4가지

maven - Java 기반 프로젝트의 라이프사이클 관리를 위한 빌드 도구 (친구 있음 Gradle)
	이에 따라 컴파일과 빌드를 동시에 수행, 테스트를 병행하거나 서버 측 Deploy 자원을 관리할 수 있는 환경을 제공한다.
	또한 라이브러리 관리 기능도 내포하고 있다.
	Java로 개발하다 보면 다양한 라이브러리를 필요로 하게 되는데, 
	pom.xml 파일에 필요한 라이브러리만 적으면 Maven이 알아서 다운 받고 설치해주고 경로까지 지정해준다.  ==> 의존성 관리!!!

DAO(Data Access Object) - 실제로는 DB의 데이터에 접근하는 객체
	Service와 DB를 연결하는 역할을 하며,
	실제로 DB에 접근하여 data를 삽입, 삭제, 조회, 수정 등 CRUD 기능을 수행
